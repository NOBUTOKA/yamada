# 即時局所反映へ統一する設計案

この文書は2026-10-31時点の検討結果であり、実装済みのアーキテクチャではない。性能比較だけでは即時/遅延の一貫した優位は得られなかったため、現在ソース・設定・位置・履歴の整合を単純にすることを設計上の採用理由として検討する。本体の操作感、保存・履歴・必要な設定順・ソース保持を維持し、編集領域の拡大を目標にしない。

## 全体構造

**編集中の正本を「現在のソースと、それに対応するモデル・位置・検証結果」の1つの確定状態にする。** 受理した編集はその場で本文と位置へ反映し、UI・保存・Diff・次の編集が同じ状態を見る。モデル値だけが先行する状態や、後で生成すべき意図のキューを確定状態として公開しない。ユーザーが直接ソースを編集しない通常経路では、外部ファイルのReloadまで正本を取り替える必要もない。

| 状態 | 役割と保持方針 |
|---|---|
| CurrentText | 現在の編集結果。唯一の編集対象本文。通常保存・Diffの右側はこれを読む |
| Components / Settings | CurrentText内の部品・明示設定の対応モデル。設定IDは固定し、値と現在位置は編集時に更新する |
| SourceIndex | 設定・文・構築文・宣言・method・不明文等の現在位置と所有関係。本文と同じRevisionで公開する |
| Revision | 確定のたびに単調増加する版。Undo/Redoでも進み、古い評価・UI通知・候補の採用を拒否する |
| StateId / History | 履歴上の状態と、可逆な差分。Undoは以前のStateIdへ戻るがRevisionは巻き戻さない |
| OpenedText / SavedImage | 最初に開いた本文、最後に書けた出力の読取専用記録。Diff・外部変更確認・保存位置のために必要だが、編集の別基準にはしない |
| Evaluation / SourceAnalysis | 現在状態から作る派生値。必要な依存範囲だけ更新/失効し、別の編集モデルを内部に保持しない |

ディスク上の保存済み内容と編集中の内容が異なること自体は必要な状態である。廃止対象は「通常編集の基準」「未反映の値」「生成済みの別モデル」を照合して選び直す二重管理であり、保存前後の比較記録まで削除することではない。MATLABの文字列共有を使い、保存比較用に全モデルをもう1個持つ設計にはしない。

## 編集の共通処理

置換・挿入・削除を、現在の版を基準とするSourcePatchBatchへ統一する。パッチは既存コードに合わせたStart/Endの文字オフセットとする（挿入はEnd = Start - 1）。行番号は表示用であり、編集の正本にしない。UTF-8のbyte数を位置差分へ使わず、現行スキャナーと同じ文字オフセットを用いる。

1. CurrentStateとカタログ版を取得し、対象SettingId/ComponentId、所有範囲、型・値・依存順を確認する。
2. 現在の位置からSourcePatchBatchを作る。変更前の期待文字列、所有ID、変更後の文字列、必要なモデル差分を含める。既存設定は原則その値の範囲を置換し、新規設定は現在の設定列/依存順/不明文境界から挿入位置を決める。constructorのName-Valueはその構文を保持する。
3. 公開状態を変更せず、候補文字列・位置変換・モデル差分を準備する。同位置の挿入順を確定し、重複範囲は結合するか拒否して、後方からパッチを適用する。
4. 変更した文の字句/構文と、対象の設定列・必要な依存先の順序/最終値を確認する。既存の独立性/型/範囲の証明を流用し、無関係な部品の値を再検証しない。証明できない場合は同じ候補を全体解析する。
5. 直前のRevisionとカタログ版が一致することを確認し、本文・モデル・全位置・診断・履歴を一括確定する。失敗/再入/古い候補なら何も公開せず破棄する。
6. カタログのgeometry影響情報からPreview・実測矩形・選択枠・クリック領域の更新要求を作る。ソース変更量を理由に全面描画を要求しない。

確定中はdrawnowやnative UI操作を呼ばず、中間状態を読めない短い区間でモデル差分を適用する。位置表と公開済みの解析結果は版ごとの独立した値とし、現在の表を書き換えて過去の公開結果まで動かさない。

履歴・保存・UIへ公開する時点では本文とモデルが一致している。文字列の組立てだけを先に確定し、後からモデル解析が失敗する経路にはしない。候補は私有の差分/値として用意し、通常の1プロパティ編集ごとに文書全体を複製しない。公開した過去の結果は独立した値として保持する。

## 設定IDと位置を分離する

現行PropertySetting.IdはSourceSnapshotId・ValueSpanの開始位置・Pathから作られ、StatementIdとInitializationScopeIdも位置に結び付いている。即時更新で同じ設定のIDを毎回作り直すと、履歴・実効値の出所・callback参照の対応まで変わってしまう。

ComponentId、SettingId、StatementId、ScopeIdは不透明な固定IDとし、位置はSourceIndexで引く。初回インポート時に従来のID文字列を割り当てることは可能だが、移動後の位置をIDから逆算したり、位置変更だけでIDを再発行したりしない。新規設定だけ新IDを割り当て、Undoで削除した設定を戻す際は同じIDを復元する。同じPathの複数記述は別IDで保持し、PropertyEntryは編集対象の明示設定と実効状態への参照を持つ。

現在位置が必要なSourceSpans、PropertyEntry.Metadata.ValueSpan、PropertySettingの各Span、SourceStatement.Span等へ独立したコピーを配り続けない。最終形では位置IDへの参照か読取専用の投影に統一する。移行中も書込みは位置表の1か所から行い、設定側・metadata側を別々に補正するコードを残さない。Originのparsed/generatedは由来の記録として残せても、反映済みかどうかを切り替えるフラグには使わない。

## 全位置情報と字句解析の更新

実験版の即時更新が扱ったのは、保持したSourceSpanの範囲索引である。本体のSourceStatement.CodeOffsets（文字ごとの位置）、SourceAnalysisの文範囲・initializer trace・callback候補・scope等の派生索引をすべて即時維持した計測ではない。実験の約1.4〜1.9秒/100編集を、そのまま本体での全解析情報更新コストとは扱わない。

- パッチより後方の範囲は差分長を加え、パッチを包含する文/method等は末尾を補正する。挿入点の左/右のどちらへ所属するかをアンカーごとに明示する。削除で失われるノードは削除し、置換内部の細分範囲は補正で推測せず作り直す。
- コード文字の位置対応は文の開始位置に対する相対オフセットへ変える。文をずらすだけで全コード文字の絶対位置を書き換える必要はなく、変更した文だけText/相対位置を取り直す。後方文の意味解析をやり直さない。
- literal置換や既知の設定文追加は、完全な文単位で局所スキャンする。複数行constructor、継続行、引用符、コメント、セル/文字列配列等は文境界を使い、「1行なら安全」と仮定しない。
- initializer traceは値だけの置換では構造を維持する。文の挿入では、その初期化区間の実行順と境界を更新する。method追加、呼出し関係変更、広域rename等は影響scopeを広げ、局所性を証明できなければ全体解析する。
- 不明文は固定IDと現在範囲を持つ境界として保持する。以前合意したユーザー責任の方針を維持し、未知の作用を推測した全部品検証へ戻さない。必要な依存設定が後ろにあれば、その後の成立する区間へ置く。

まずは単純な文字列と数値配列による一括位置更新を採用候補とし、piece tableやropeを前提にしない。通常の部品数で範囲補正が支配的になった時にだけ別のデータ構造を検討する。SourceAnalysisを毎回丸ごと捨て、次の読取りで全文スキャンするだけの実装を「即時局所化完了」としない。

## Undo/Redo

通常履歴は「モデル値の変更意図」から「確定した本文/モデルの可逆差分」へ変える。各履歴辺に、適用前後のStateId、forward/inverseのパッチ、変更前後の小さいモデル記録、作成/削除した固定IDと所有関係を持つ。新規追加・設定削除・Reset・部品移動も1つの履歴単位にまとめる。

Undoは現在が辺のAfterStateIdに一致することと期待文字列を確認し、逆パッチ・逆位置変換・モデル復元を同じ確定経路で適用する。RedoはBeforeStateIdから正方向へ適用する。新規設定をUndoした直後に別の新規設定を挿入する場合も、現在位置から処理でき、保存や全文生成を間に挟む必要はない。逆方向適用後も必要な字句/位置整合を確認するが、以前確定した値のnative検証を無条件に全件再実行しない。

単調なRevisionは状態の同一性と分けるため、Undoで古いキャッシュが復活することはない。SavedStateIdは履歴の配列番号だけに依存せず、枝の破棄や履歴上限でも取り違えない。IsDirtyの既存の保守的な挙動は今回勝手に変更せず、保存点との本文一致等を内部で使う場合もUIの可否/表示契約を別に確認する。通常編集では全モデル/全文を履歴ごとに複製せず、広域編集で必要な場合だけ私有の前後スナップショットを許す。

## 保存・Diff・Reload

通常保存はCurrentTextを読み、現在Revision/カタログ版に対応した一時的な保存候補を作る。移行初期は現行と同じ全体再解析・既知状態/要求値/親子の一致確認を残すが、未反映意図から再生成した別ソースとの比較は行わない。保存中にRevisionが変わっていないことを確認し、書込み成功後だけSavedImageと保存点を更新する。失敗時に現在の本文・履歴・保存先を変更しない。

現行SavedSourceCheckpoint.assertCurrentはstructuralCandidateとRoundTripGeneratorを使って変更意図を再生成する。ここはCurrentTextと確定状態/Revisionの照合へ置き換える。保存のためだけに独立した編集可能Documentを常駐させず、解析したoracleは検証用の私有結果として扱う。保存時全体検証を即時方式への移行だけを理由に省かない。

エンコードと改行の正規化はSourceWriterの出力投影として明示する。CurrentTextと書込み文字列が異なる場合、保存したbyte/位置の読取専用記録と、その現在位置への対応を保持する。保存用の位置を編集位置として流用しない。UTF-8/BOM/CRLFと既存の入力保持契約を、暗黙の本文置換で変えない。通常の単一改行形式では両文字列は一致する。

Save Asでclass/constructor名が変わる場合は、既存AppClassIdentityRewriterの認識範囲から現在本文のパッチを作り、保存候補へ適用する。書込み成功時だけ現在状態へ昇格する。Save As後にUndoしたプロパティ変更を保存しても新しいclass名が維持される契約を守るため、履歴のclass識別/位置/関連するパッチを保存先のidentityへ再写像する。これを保証する前にSave Asを新方式へ切り替えない。保存だけの移行のためにUndo項目を1個増やす仕様変更は行わない。

Diffの右側はCurrentText、左側は既存UIの比較基準（元の読込ソース）を読む。Diffを開くための生成は不要になる。外部ファイル検出と確認・Cancel後の方針は既存のLifecycleへ委ね、Reload受理時に全体解析した新しい確定状態へ原子的に置き換える。

## 構造編集・callback・新規文書

| 操作 | 同じ経路への載せ方 |
|---|---|
| 既存値の置換 | 現在ValueSpanへのパッチ。設定IDと記述方式を保持 |
| 設定追加 | 現在の設定列/constructor引数位置へ挿入し、新ID/位置/順序を同時登録 |
| 設定削除/Reset | 所有する値・引数対・設定文だけ削除し、次の有効設定/既定値を確認。空になった行だけ整形 |
| 部品追加/貼付け | 宣言・構築・設定のまとまりを挿入し、モデル/名前/位置を同時追加 |
| 部品削除/Cut | 所有範囲の削除と参照/callbackの既存方針を1トランザクション化 |
| 親変更 | 選ばれた移動先で判定し、構築先と配置設定、必要な記述位置を変更。表示時の全候補判定を復活させない |
| rename | 既存の認識範囲に限定した同時置換。単なる文字列全置換にしない |
| callback Add/Delete | bindingと必要なmethodテンプレートを同時編集。geometryを更新しない |
| New | canonical generatorで最初の本文/位置を1回作り、その後は開いた文書と同じ経路を使う |

既存の生成器やSourceEditsはまず「現在状態からパッチを作る部品」として再利用し、先に全部書き直さない。広い編集で全体解析が必要でも、コマンド内で一度完成した候補を解析し、成功時にCurrentStateへ確定する。後で反映するキューを残さない。構文/所有範囲を証明できない操作を新たに許可する設計ではない。

## 廃止・縮小する現行状態

CurrentTextへの移行後、GeneratedTextを別の編集結果として保持する必要はなくなる。PropertyCheckpoint/combined configurationは別ソースを持つ編集可能なモデルから、現在版に対応する読取専用の検証結果へ縮小する。PendingEdits、RenameEdits、CallbackEditsは準備中トランザクションの内部データにし、確定後に残さない。complete-insertion-source等の「現在値を後で出力する」キャッシュも廃止対象である。

OriginalTextは既存テスト/元ソースDiffのための読込時記録として残せるが、sourceAnalysisや新しい編集の基準には使わない。PropertyEntryとPropertySettingに同じ設定の旧値/新値を常駐させる役割分担は、現在の明示設定と派生した実効値へ整理する。SavedSource全モデルは保存byte/必要な位置と検証証明の記録へ縮小する。現在版だけで足りる箇所に新旧モデルの一致比較を残さない。

DocumentModel/ComponentRecordは現在低水準の公開mutatorを持つ。管理中の文書について、これらの直書きからモデルだけを変更できるままにはしない。内部呼出しは共通トランザクションへ移し、未接続のテスト用builder/単独モデルは明示的に別段階として扱う。想定外の直書きを検知した場合に、読取りのたびに暗黙の生成を行う逃げ道を作らない。カタログ変更はソースの書換えではなく検証結果の失効として扱う。

## 移行手順と判定基準

1. 現在本文・固定ID・位置表・Revision/StateId・可逆パッチの基盤を作る。置換/挿入/削除の期待文字列と位置変換を、独立した全体parserをoracleに確認する。位置に由来するIDの比較/再生成箇所を先に洗い出す。
2. 既存リテラルと新規リテラルを同時に接続し、現在のカタログ条件で可能な全コンポーネント/全設定へ適用する。ResetとUndo/Redoも同じ差分経路へ載せる。最小検証後に特定プロパティだけの実装を残さない。
3. SourceAnalysisの局所更新を接続する。通常編集の直後の選択・Preview・callback可否照会まで含めて、遅れて全文解析が走っていないことを確認する。
4. 保存/Diff/ReloadとSave Asの履歴identityを接続する。保存前後の追加/置換/削除、Undo/Redo後の再保存、失敗・外部変更、混在改行、Unicode・相対画像パス、readonlyの元ソース保持を確認する。既存の「OriginalText/settingSnapshotが変わらない」内部テストは、元ソース保持・固定ID・現在位置/値・履歴を検証するテストへ置き換える。
5. 構造編集、rename、callback、新規文書を現在本文へのトランザクションに順次接続する。未移行の操作は互換アダプターでコマンド内に完結させ、コマンドをまたぐ遅延意図は持たせない。
6. 最後の読み手を接続した後、古い生成キャッシュ・別モデル・重複位置metadata・compatibility adapterを削除する。常設の二方式切替を完成形にしない。共通契約への移行段階で全体回帰を行う。

第一の採用基準は、各確定後の本文/設定/位置/IDと履歴・保存の整合である。性能はbacd6b4の遅延試作と現在本体を区別し、同じ3構成・異なる設定・文字数が変わる10/50/100編集と保存で測る。字句/trace/可否の次の読取りを含め、解析・複製・範囲更新・メモリ/履歴量を確認する。即時方式なら自動的に速いとは主張しない。

局所性を証明できない構造/構文をコマンド内の全体解析へ戻すことは許すが、通常の独立リテラルまで恒常的にそこへ戻る場合は未完了とする。整合性不一致・古い位置・非原子的な失敗を検出した場合はその経路を止めて修正する。現方針で追加短縮/単純化が見込めなくなった時、保証/操作感/保存・履歴の意味を変更する必要が出た時は、根拠と代案を示して相談する。

## 現時点の判断

即時局所反映で、現在のソースを基準に編集・検証・表示・保存を統一する設計は成立する見込みがある。最も重要なのは文字列の更新速度ではなく、固定IDと位置・字句索引・可逆履歴を同時に扱い、確定後に別の編集状態を残さないこと。ここを整えず実験版の即時索引だけを本体へ追加すると、管理対象が増えるだけになる。単純化を目的にするなら、古い状態と読み手を実際に廃止するところまでを移行の完了条件にする。
