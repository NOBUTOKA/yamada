# atomic表示更新の集約と性能検証（2026-11-01）

続く位置・入力スナップショットの差分更新と検証結果は[次段階の報告書](PROJECTED_INPUT_PERFORMANCE.md)を参照する。

Previewと周辺UIへの変更を適用し、必要な場合だけR2024aの`stabilize()`応答を待ち、共通のCanvas相対矩形から周辺配置と境界表示を作る経路へ集約した。geometryに影響しない設定では安定待ちと矩形収集を省く。操作感・ソースの即時反映・現在位置・保存・履歴・設定順・fit検証・公開値の独立性を維持する方針で、特定の部品名・プロパティ名による最適化リストは追加していない。

## 呼出し回数と残る負荷

200部品3配置について、通常計測とは別の実行で同じ13編集をプロファイルした。プロファイラー時間は通常の待ち時間へ代入しない。以下の時間は子処理を含むため、行同士を合算しない。

| 処理（13編集の合計） | Gridなし | 単層Grid | 8段Grid |
| --- | ---: | ---: | ---: |
| 全体入力のcapture | 13回・5.496秒 | 13回・8.918秒 | 13回・9.330秒 |
| ソース位置投影の適用 | 2665回・4.775秒 | 2704回・8.223秒 | 2795回・8.391秒 |

位置投影の準備・適用は現在も全部品の必要な位置を扱う。検証は各投影につき1回へ減らし、無変更の位置・metadata・設定の再代入を省いた。表示正規化は従来の26回から14回へ減ったが、変更後の全体正規化は毎回残る。入力captureに伴う`EvaluationContext.freeze`は142409/234997/244565呼出し、自己時間は4.126/6.634/6.935秒で、主要な残存負荷である。

Gridありの5件は各1回の収集で、実在する各Gridの構築も1収集につき1回だった。buildの総数20/55には各5回の空Grid用payload作成を含み、実在Gridは3×5回/10×5回である。通常編集内の`RoundTripGenerator.generate`、`AppSourceParser.parseText`、レイアウト再確認用タイマーの開始・反復はいずれも0回だった。必要な安定待ちと計測を1回にまとめる方針は成立しているが、geometry更新時の表示データ組立にも負荷が残る。

## 次の修正候補

1. 位置だけが変わった設定について、変更のないLiteralValue・ValueKind等を再適用しない。現在は位置が変わると`applySourceSetting`が値とmetadataをまとめて再代入するため、同じ値の入力追跡・再帰検査を繰り返す。まずこの重複を減らし、文字数が変わる置換・追加、同じ文字数の値変更、Undo/Redo、保存の一致を維持する。
2. 検証済みのソース投影を、内部の凍結済み入力と表示比較用データへ引き継ぐ。前後の入力追跡token・ソース状態・カタログ世代が一致する管理された遷移だけを対象とし、更新済みの位置と値を再取得・再freezeしない。管理外変更・mutable値・未対応の遷移は現行の全体取得へ戻す。公開結果の独立性を維持し、特定の型やプロパティに限定しない。
3. その後の実測で残る場合、選択時のInspectorと、geometry更新時の部品descriptor・可視性・選択/移動表示の組立を分離してプロファイルする。今回1回へ集約した矩形を取り直す方式へは戻さず、変更しない情報の再構成を減らす。

これは元の「内部共有・差分適用」の工程の継続である。まず現在の保証を保てる重複削減から試し、各変更の通常時間と呼出し回数で判断する。現在の対象・方針で追加短縮が見込めなくなった時、または保証・責任範囲・操作感の変更が必要になった時に相談する。

## 検証と互換性

固定Canvasから1回収集して外周を配置する隔離実験は、Gridなし・単層・8段、12/200部品の44操作で、後から独立に得た矩形・外周・境界表示と一致した。関連検証は初回66件中58件が合格し、失敗8件を含む修正後22件がすべて合格した。したがって関連66種類をカバーした合成結果であり、初回66件を一度で全件合格とした記録ではない。その後、最終実装`d44379e`に対する全体回帰881件を実行し、881件すべて合格した（失敗0、未完了0、合計6557.528秒・約109分）。この881件は一度の全体実行による結果である。

非公開ルートの依存・失敗時の回復・他バージョンでの確認事項は[ARCHITECTURE.md](ARCHITECTURE.md#preview-layout-completion-matlab-r2024a)に記す。`stabilize()`単独ではネイティブFigure自体のウィンドウサイズ変更の通知完了まで保証しなかったため、実際のPreviewと同じ固定CanvasでAxes・Table・HTML・Tabを検証した。別バージョンの互換性や物理画面への表示完了は保証していない。
